# 物流报价系统（云途 + 云途商派 + 壹号物流 + 远朋物流 + 燕文物流 + UBI）

这是一个可以在维护 Mac 本地运行、也已具备 Cloudflare Pages 部署结构的
多物流公司报价系统，用来完成以下流程：

1. 搜索或选择国家，输入商品成本、计费重量（默认千克）、利润和汇率；
2. 从当前国家已开通的渠道中选择本次产品可以使用的渠道；
3. 计算所选渠道的人民币运费和美元最终报价；
4. 需要比价时，使用结果区域中的“比较全部可用渠道”单独进行比较。

页面顶部的“批量报价”支持一次处理多件商品：

1. 从 Excel/WPS 复制 `SKU、商品成本、计费重量` 三列并粘贴；
2. 统一填写每个 SKU 的利润和美元兑人民币汇率；
3. 选择一个物流渠道，并勾选该渠道已经开通的多个国家；
4. 一次生成“SKU × 国家”的最终美元报价矩阵；
5. 将结果复制回 Excel/WPS，或下载 UTF-8 CSV 文件。

批量报价单次最多支持500个SKU。数据可以带表头或不带表头，计费重量默认使用
千克；带`g/克`单位的表头或数值也会自动换算。重复SKU、无效成本和无效重量
会在计算前提示。
批量报价与单件报价共用完全相同的物流费率、税费、分区加权和向上取整规则。

## 本地版与公司共享版

系统支持以下两个入口：

- **本地版**：开发和离线备用时在 Mac 上双击 `start.command`；
- **公司共享版**：部署在 Cloudflare Pages，任何同事通过浏览器访问，负责单件
  报价、批量报价以及新版物流 Excel 更新；不需要登录。

七家物流公司的同一套已验证解析规则会在浏览器中运行。任何同事都可以在
Windows、Mac 或其他设备的共享网页里选择新版价格表、查看差异并确认更新。
确认后的当前版本统一保存在云端，其他人刷新网页即可使用；不会把版本历史分别
留在每位同事的电脑里。若两位同事同时基于旧版本操作，后提交者会被提示刷新，
避免无意覆盖别人刚更新的价格。

GitHub 只作为代码仓库和 Cloudflare 自动发布来源，不使用 GitHub Pages。
PWA 目前不需要；它只是以后可选的“安装到桌面”外观，不影响网页的跨设备访问。

共享版启动时会读取 Cloudflare KV 中唯一一份“当前使用价格”。如果首次部署时
KV 还没有数据，网页会自动使用代码内置的已验证价格，不会出现空白页面。

## 启动

最简单的方法：

1. 在 Finder 中依次打开“文稿（Documents）→ Codex → 物流报价系统”；
2. 双击 `start.command`；
3. 终端窗口出现“物流报价系统已启动”后，浏览器会自动打开。

如果浏览器没有自动打开，再访问：
[http://localhost:8000](http://localhost:8000)

如果 macOS 第一次阻止打开：按住 Control 点击 `start.command`，选择“打开”，再确认一次。

也可以在终端进入本文件夹后运行：

```text
python3 server.py
```

直接双击 `index.html` 仍可使用报价计算，但价格更新功能必须通过
`start.command` 启动，以便在本地保存价格版本。

## 停止

回到启动时出现的终端窗口，按：

```text
Control + C
```

然后关闭该窗口即可。

## 更新物流价格

1. 双击 `start.command` 启动系统；
2. 打开 [http://localhost:8000](http://localhost:8000)；
3. 点击页面顶部的“价格更新”；
4. 选择新版云途、云途商派、壹号、远朋、燕文或UBI物流 `.xlsx` 文件；
5. 点击“检查并生成差异预览”；
6. 查看新增、变更、删除及未变化的费率数量；
7. 核对具体价格差异；
8. 确认无误后，点击“确认启用新价格”。
9. 在公司共享网页中确认后，标准化费率会直接更新到统一当前版本；其他同事刷新
   页面即可使用。

价格会继续保留。缺少工作表、表头异常、渠道区块缺失、重量档位无法识别、
费率重复或档位异常时，更新会被拒绝。

## 当前计算规则

```text
计费重量 = 实际重量与该渠道最低计费重中的较大值，再应用该档位进位制
重量档位 = 按计费重量匹配，档位上限包含、下限不包含
运费 = 计费重量（千克）× 公斤单价 + 挂号费
最终美元报价 =（商品成本 + 固定利润 + 运费）÷ 美元兑人民币汇率
```

人民币运费四舍五入到小数点后两位；最终美元报价不使用普通四舍五入，
而是始终向上取到小数点后一位。例如 `16.96428571 → 17`、
`3.25 → 3.3`、`78.78 → 78.8`。

壹号美国标准线5千克以内按1克进位，5千克以上按1千克进位；壹号英国
和欧洲渠道最低50克计费并按1克进位。壹号价格表中的“处理费”作为每票
固定费用参与运费计算。

壹号加拿大、英国、欧洲和美国SWD渠道最低50克计费并按1克进位；壹号
澳大利亚特货A最低10克计费并按1克进位，价格表中的4个邮编区按公司
30%/30%/30%/10%规则统一加权。

UBI渠道按1克进位。总价格表只使用大陆上门揽收价格；新西兰按公斤价加
操作费计算，且不增加任何税费。UBI澳邮普货/带电的4个区域按
30%/30%/30%/10%加权。UBI加拿大特价按重量档位匹配上门揽收的每公斤价和
每件操作费。

远朋标准小包、美国食品和新西兰偏远渠道按1克进位并最低50克计费；
远朋E邮宝按1克进位，其中新西兰、巴西、日本、哈萨克斯坦最低50克，
乌克兰最低10克。其他E邮宝国家按价格表中的重量范围计算。

燕文常规公斤费率按1克进位，并采用每个国家/重量档在原表中列出的最低计费重。
燕文专线追踪的日本费率按500克首重及500克续重计算；燕文轻小件日本费率
按100克首重及100克续重计算。页面中的“处理费”已包含在对应固定费用中。

页面中的重量由使用者在向供应商确认产品重量和体积后填写，代表已经核对过的
实际计费重量；输入和批量导入的默认单位均为千克，系统不再重复计算体积重。

云途商派价格表中的进位制为空，因此系统直接使用已经确认的计费重量；表中
明确写出的最低计费重继续生效。美国/加拿大商派渠道均按对应重量档的公斤价
加挂号费计算，保价、签名及邮编偏远费用当前不自动加入。

## 公司业务调整规则

系统保留物流公司的原始费率，并在计算时通过独立规则进行调整：

- 欧盟 27 国：所有渠道挂号费增加 ¥24；
- 英国：所有渠道挂号费增加 ¥2；
- 澳大利亚：当渠道包含 1、2、3、4 区时，公斤单价和挂号费均按
  `30% + 30% + 30% + 10%` 加权；
- 澳大利亚只有3个分区时，公斤单价和挂号费均按每区三分之一等权平均；
- 墨西哥：只允许云途精选普货和云途精选带电报价；其他所有渠道均排除。
  原“云途特惠带电墨西哥税费”规则已作废，不再参与任何计算；
- 新西兰：普货和带电使用UBI且不加税；云途化妆品继续增加 ¥8.72，
  远朋新西兰偏远专线保留用于偏远地址；
- 规则中指定的渠道国家税费会与欧盟或英国规则累加。

例如罗马尼亚在云途特惠普货和云途特惠带电中，会同时增加欧盟税费
¥24 和渠道国家税费 ¥41，合计增加 ¥65。

云途标快普货和云途标快带电的澳大利亚价格表目前只有3个分区，系统按
每区三分之一计算统一均价。

远朋6条标准小包线路的澳大利亚价格有4个分区，按30%/30%/30%/10%加权；
远朋E邮宝澳大利亚价格没有分区，直接按价格表单一费率计算。

燕文专线追踪普货、特货和化妆品专线的澳大利亚价格有4个分区，按
30%/30%/30%/10%加权；燕文航空挂号普货和特货采用原表单一区费率。

UBI澳邮普货和带电均有4个分区，按30%/30%/30%/10%加权。

## 文件说明

- `index.html`：网页内容；
- `styles.css`：网页外观；
- `channel-data.js`：7个物流服务组、55个渠道的价格快照；
- `business-rules.js`：通用税费、国家指定渠道和澳大利亚加权规则；
- `pricing.js`：多渠道匹配与报价计算规则；
- `app.js`：表单交互和结果显示；
- `batch-pricing.js`：批量数据识别、矩阵计算和CSV/表格导出；
- `batch.js`：批量报价页面交互；
- `updater.js`：价格检查、差异预览和版本恢复界面；
- `web-importer.js`：在Windows、Mac等设备浏览器中启动Excel解析并生成差异预览；
- `cloud-data.js`：优先读取共享价格，失败时安全回退至内置价格；
- `bootstrap.js`：等待价格载入后再按顺序启动报价页面；
- `importer.py`：云途、云途商派、壹号、远朋、燕文与UBI Excel解析、比较和版本管理；
- `server.py`：只在本机运行的网页与更新服务；
- `functions/api/prices.js`：Cloudflare KV当前价格读取、更新和版本冲突保护接口；
- `functions/api/status.js`：区分本地维护版与公司共享版；
- `tools/build_cloud.py`：只生成可公开部署的网页目录，不包含本地价格历史；
- `cloud-config.example.json`：首次部署后填写同步地址的示例，真实配置不会进入Git；
- `data/current-prices.json`：当前使用的物流原始价格；
- `data/version-history.json`：价格版本记录；
- `data/versions/`：可恢复的历史价格快照；
- `tests/pricing.test.js`：自动测试；
- `tests/importer.test.py`：价格导入与版本恢复测试；
- `tests/cloud.test.py`：共享价格接口、未配置保护与发布目录隔离测试；
- `start.command`：双击启动；
- `test.command`：双击测试。

## Cloudflare 首次部署

跨平台 Excel 更新代码已经接入。首次部署时需要一次性完成：

1. 把项目代码放入 GitHub 仓库；
2. 在 Cloudflare Pages 连接该仓库；
3. 设置构建命令为 `python3 tools/build_cloud.py`，输出目录为 `dist`；
4. 创建一个 KV 命名空间，并以 `PRICE_DATA` 绑定到 Pages Functions；
5. 发布当前价格，再由一位同事在 Windows 或其他设备试算并测试价格更新。

以上步骤会涉及 Cloudflare 页面和首次生成的网址，由 Codex 逐项引导，不需要
额外购买域名或安装物流软件。
